## 0. Этап 1.6 — стабилизация (ворота перед Этапом 2)

Этап 2 не начинается, пока не закрыто следующее.

1. **Результаты теста на телефоне.** Владелец прогоняет debug APK и присылает список проблем. Каждую проблему занести в `docs/PROGRESS.md` (симптом, шаги, лог), затем исправить.
2. **Чек-лист ручной проверки Этапа 1** (владелец ставит ✅/❌):
   - подключение по LAN/Tailscale, `/global/health`, версия сервера в UI;
   - создание сессии, prompt, стриминг, остановка (Stop);
   - tool-карточка, шторка с полным выводом, поиск и копирование;
   - Approve / Reject разрешения;
   - неверный пароль → понятное сообщение (401);
   - `http://` без тумблера блокируется;
   - свернуть приложение на 5 минут → вернуться → reconcile подтянул пропущенное;
   - перезапуск приложения → история сессий на месте.
3. **Технический долг:**
   - вынести Room (профили, сессии, сообщения, tool calls) из `:data:opencode` в отдельный модуль `:data:local`, чтобы будущие адаптеры (ACP) не зависели от OpenCode;
   - у `MessageEntity` и `ToolCallEntity` должны быть `profileId` и `sessionId` (составные ключи, каскад);
   - убедиться, что CI зелёный;
   - перепроверить версии библиотек: взять актуальные стабильные и совместимые (Kotlin ↔ KSP ↔ Hilt ↔ Room ↔ AGP) по официальным страницам релизов, а не из памяти;
   - зафиксировать `minSdk` / `targetSdk`.
4. **Версия OpenCode.** Локальный сервер, на котором писались фикстуры, был версии 1.2.27, а проекты-аналоги (AndCode) пинят 1.18.x. Решить, какую версию пинить для локального runtime (раздел 2.1), обновить сервер на ПК до неё, **перезаписать фикстуры**, указать версию в `docs/opencode-api-notes.md`, прогнать контрактные тесты. Расхождения в API зафиксировать.
5. **Чистка фикстур:** скрипт, вырезающий пути вида `C:\Users\...`, токены, имена проектов; фикстуры снимать только в тестовом пустом проекте.

Приёмка 1.6: чек-лист выше зелёный, CI зелёный, `PROGRESS.md` заполнен.

## 1. Цель Этапа 2

Приложение работает **без ПК**: на телефоне поднимается `opencode serve`, а PocketCLI подключается к нему как к обычному профилю типа «Local». Весь Этап 1 (чат, карточки, reconcile) переиспользуется без изменений — отличается только `Transport`.

Не входит в Этап 2: ACP и другие агенты, встроенный терминал, доступ к `/sdcard`, расписания, «Колода».

## 2. Шаги

### 2.0 Спайк (отдельная ветка `spike/proot`, без UI) — делаем первым

Цель — за пару дней убедиться, что запуск вообще возможен на реальных устройствах. Если не получилось, дальше не идём, а пересматриваем подход (раздел 5).

Прочитать перед началом (AndCode под MIT, идеи и код можно адаптировать с записью в `THIRD_PARTY_NOTICES.md`):
- https://github.com/yuga-hashimoto/and-code — `docs/LOCAL_RUNTIME.md`, `THIRD_PARTY_NOTICES.md`, `app/src/main/assets/local-runtime-manifest.json`, каталоги `runtime_tools/` и `scripts/` (как собирается proot);
- https://github.com/yuga-hashimoto/opencode-android — предшественник AndCode, проще по объёму;
- https://huggingface.co/SmallAICreator/cinder — описание рецепта proot + 4 МБ Alpine (musl).

Шаги спайка:
1. Положить `proot` и его loader в APK как `jniLibs/arm64-v8a/lib*.so` (для эмулятора ещё `x86_64`). В Gradle: `packaging { jniLibs { useLegacyPackaging = true } }`, `android:extractNativeLibs="true"`. Запускать из `ApplicationInfo.nativeLibraryDir` (это обходит запрет exec из `filesDir` для targetSdk ≥ 29). Источник бинарников: сборка из `termux/proot` через NDK или способ, который использует AndCode **[ПРОВЕРИТЬ]**.
2. Скачать Alpine minirootfs (официальный CDN, aarch64), распаковать в `filesDir/rootfs-spike`.
3. Запустить: `proot -r <rootfs> -0 ... /bin/sh -c 'echo hi'`. Флаги, переменные окружения (`PROOT_LOADER`, `PROOT_TMP_DIR` в кэш приложения), bind-монты `/dev /proc /sys`, `--link2symlink`, `--kill-on-exit` взять из AndCode и `proot-distro` **[ПРОВЕРИТЬ]**.
4. Скачать **musl-сборку** OpenCode с GitHub Releases (в AndCode используется именно musl-бинарник; точное имя ассета смотреть на странице релизов OpenCode, не угадывать), положить в rootfs, выполнить `opencode --version`.
5. Запустить `opencode serve --hostname 127.0.0.1 --port <N>` с `OPENCODE_SERVER_PASSWORD`, дернуть `/global/health` из приложения по loopback.

Приёмка 2.0 (таблица в `PROGRESS.md`, минимум 2 реальных устройства + эмулятор): шаги 3–5 пройдены, указаны модель телефона, версия Android, время старта сервера, потребление RAM.

### 2.1 Манифест рантайма `local-runtime-manifest.json`

- Поля: версия манифеста; для каждого артефакта (proot-инструменты, Alpine rootfs, OpenCode) — `url`, `sha256`, `sizeBytes`, `abi`, `version`.
- Версии **пиновать** (одна проверенная версия OpenCode, совпадающая с версией, на которой сняты фикстуры). Обновление версий — только через релиз приложения.
- Валидация манифеста при чтении (схема), ошибка при несовпадении ABI.

### 2.2 Установщик (`:runtime:local`)

Машина состояний: `NotInstalled → Downloading(progress) → Verifying → Extracting → Configuring → Ready | Failed(reason)`.

- Проверка свободного места **до** скачивания (по размерам из манифеста + запас).
- Докачка (HTTP Range), проверка SHA-256 после скачивания, при несовпадении — удалить и показать ошибку.
- Распаковка во **временную** директорию, затем атомарное переименование. Сохранять симлинки, права и **hardlinks** (в AndCode отдельный фикс про потерю hardlinks при активации рантайма) **[ПРОВЕРИТЬ как сделано у них]**.
- Конфигурация rootfs: `/etc/resolv.conf` (в Android его нет — записать DNS), `/etc/hosts`, корневые сертификаты (`apk add ca-certificates`), `apk add git bash curl ripgrep` — все команды выполняются тем же proot.
- Файл-маркер установленной версии; «Восстановить» (переустановка без потери рабочих папок) и «Удалить рантайм».
- Устойчивость к смене/обновлению APK: после обновления приложения runtime должен остаться рабочим (в AndCode был такой баг-фикс).

### 2.3 Супервайзер процесса `LocalRuntime : Transport`

- Старт/стоп/рестарт `opencode serve`: случайный свободный порт на `127.0.0.1`, **случайный пароль на каждый запуск** (в памяти, передаётся через окружение), health-check с таймаутом.
- Профиль типа `Local` создаётся автоматически, URL и пароль подставляются супервайзером. Политика cleartext: loopback разрешён без предупреждения.
- Захват stdout/stderr в кольцевой буфер для экрана логов.
- Причина завершения процесса: `ApplicationExitInfo` + код выхода → в лог и в UI.
- Авто-рестарт с backoff (ограничить число попыток), при исчерпании — статус `Failed` с кнопкой «Перезапустить».
- Остановка убивает всё дерево процессов; pid-файл + очистка «осиротевших» процессов при следующем старте.

### 2.4 Foreground Service и уведомления

- Сервис запускается, когда начинается прогон агента, останавливается через N минут простоя. Тип foreground service и нужные разрешения для Android 14/15 выбрать по официальной документации **[ПРОВЕРИТЬ]**; запрос `POST_NOTIFICATIONS` на Android 13+.
- Постоянное уведомление: статус агента, кнопка «Остановить», тап открывает чат.
- Канал «Требуется действие»: на `PermissionRequested` — уведомление с кнопками Approve / Reject (PendingIntent → BroadcastReceiver → `AgentSessionRepository.respondPermission`).
- Подсказки пользователю: отключить агрессивную экономию батареи для приложения; на Android 12+ система может убивать дочерние процессы приложения (phantom process killer) **[ПРОВЕРИТЬ актуальные детали]**. Фиксировать случаи в логе.

### 2.5 Рабочие папки (workspaces)

- Только приватное хранилище приложения: `filesDir/workspaces/<name>`, монтируется в rootfs как `/workspace`.
- Действия: создать пустую папку, `git clone <url>` (выполняется через тот же proot, вывод стримится в UI), удалить.
- Создание сессии привязывается к выбранной папке; **как OpenCode принимает рабочую директорию** (заголовок или параметр) — посмотреть в сохранённой OpenAPI-спеке и `opencode-api-notes.md` **[ПРОВЕРИТЬ]**.
- Работа с `/sdcard` и SAF — отдельный этап.

### 2.6 Провайдеры и ключи для локального агента

- Экран «Провайдеры»: ввод API-ключа → `SecretStore` (Keystore).
- Предпочтительный способ передать ключ агенту — **переменные окружения при запуске процесса**, чтобы ключ не лежал в файлах rootfs. Если в API OpenCode есть эндпоинт для авторизации провайдеров, рассмотреть его **[ПРОВЕРИТЬ в OpenAPI-спеке]**.
- Не логировать ключи и не включать их в дампы/фикстуры.
- Рассмотреть режим «бесплатные модели» для первого запуска без ключей, если OpenCode это поддерживает **[ПРОВЕРИТЬ]**.

### 2.7 UI

- Экран «Локальный рантайм» (в Настройках): статус, версия, размер на диске, кнопки «Установить / Запустить / Остановить / Восстановить / Удалить», прогресс установки с этапами, просмотр логов (хвост буфера, копирование).
- Онбординг: если нет ни одного профиля, предложить «Запустить на этом телефоне» с оценкой размера и времени.
- Понятные ошибки: нет места, нет сети, хеш не совпал, процесс упал (с кодом), порт занят.

### 2.8 Тесты

- Юнит-тесты: парсинг и валидация манифеста; проверка SHA-256; докачка на `MockWebServer`; распаковка tar с симлинками и hardlinks на маленькой тестовой фикстуре; машина состояний установщика; backoff супервайзера.
- Инструментальные тесты (эмулятор x86_64 и/или устройство): запуск proot, старт и остановка процесса без «сирот».
- Ручной прогон: таблица устройств в `PROGRESS.md` (модель, Android, результат, время установки, замеченные проблемы).

## 3. Приёмка Этапа 2

- Установка «с нуля» ≤ 5 минут на хорошем канале; прогресс виден, этапы понятны.
- Чат работает **в авиарежиме после установки** (с локальной моделью/без обращения к ПК; если нужна облачная модель — с сетью, но без ПК).
- Приложение свёрнуто на 10 минут: сессия жива, либо процесс корректно перезапущен и состояние восстановлено через reconcile.
- «Смахнул приложение» → `ps` внутри rootfs не показывает осиротевших процессов.
- Перезагрузка телефона → рантайм в статусе «Установлен», запускается одной кнопкой.
- Обрыв сети при скачивании → докачка с того же места; нехватка места → понятная ошибка до скачивания.
- Approve/Reject работает из уведомления.
- Все проверки отмечены в `PROGRESS.md` с указанием устройств.

## 5. Риски и запасные варианты

| Риск | Что делаем |
|---|---|
| proot не стартует на части устройств/версий Android | Матрица устройств; запасной вариант запуска через системный linker (описан в статье на Habr: https://habr.com/en/articles/943188) **[ПРОВЕРИТЬ]**; в крайнем случае оставляем только Remote |
| Низкая скорость файловых операций (proot использует ptrace) | Держать репозитории внутри приватного хранилища, не на `/sdcard`; оптимизации — отдельный этап |
| Система убивает процесс | Foreground Service, `ApplicationExitInfo`, авто-рестарт, reconcile |
| Большая нагрузка на RAM/нагрев | Показывать предупреждение; замерить в спайке; в планах — «Бессмертная сессия» (заморозка при перегреве) |
| Лицензии (proot GPL-2.0, Alpine) | proot запускается как отдельный процесс; всё в `THIRD_PARTY_NOTICES.md`; условия распространения GPL-кода проверить **[ПРОВЕРИТЬ]** |
| Распространение через Google Play | Политики про скачивание и исполнение кода — **[ПРОВЕРИТЬ]**; планировать GitHub Releases / F-Droid |
| Обновление OpenCode ломает API | Пин версии в манифесте, контрактные тесты на фикстурах |
